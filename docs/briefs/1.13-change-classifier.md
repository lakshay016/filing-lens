## Taxonomy (SPEC §7.1)

Annotation labels → training class: `formatting_reorder`, `boilerplate_refresh` →
`cosmetic`; `numeric_rollforward` → `rollforward`; `new_topic`, `removed_topic`,
`substantive_reword` → `substantive`.

Rules decide first and the model never sees those edges: `unchanged` edges are ignored;
`rollforward` edges are class `rollforward`. The model is therefore **binary in
practice** (cosmetic vs substantive) on `modified`, `moved`, `split`, `merged`, `added`,
`deleted` edges, but is implemented as a general K-class softmax and trained on whatever
classes occur in the labels (an author label of `numeric_rollforward` on a `modified`
edge is legitimate and makes it three classes). `p_rollforward` is `1.0` for rule-decided
edges and the model's probability (or `0.0` if the class is absent) otherwise.

## `softmax.py` — the author's own implementation, NumPy only

```python
@dataclass(frozen=True)
class SoftmaxModel:
    classes: tuple[str, ...]
    W: np.ndarray            # (n_features, n_classes)
    b: np.ndarray            # (n_classes,)
    mean: np.ndarray; scale: np.ndarray     # feature standardisation fitted on training data
    l2: float

def fit_softmax(X: np.ndarray, y: Sequence[str], *, l2: float = 1.0,
                class_weight: Literal["balanced"] | None = "balanced",
                max_iter: int = 500, tol: float = 1e-6) -> SoftmaxModel
def predict_proba(model: SoftmaxModel, X: np.ndarray) -> np.ndarray
def loss_and_grad(params, X, Y_onehot, sample_weight, l2) -> tuple[float, np.ndarray]
def save_model(model, path: Path) -> None; def load_model(path: Path) -> SoftmaxModel   # .npz
```

- Loss: weighted mean cross-entropy + `l2 / (2 n) * ||W||²` (bias not regularised).
- `balanced` weights: `n / (K * count_k)` per sample.
- Standardise features (zero mean, unit variance; constant columns get scale 1).
- Optimiser: `scipy.optimize.minimize(method="L-BFGS-B", jac=True)` on the flattened
  parameters, starting from zeros. Log-sum-exp for numerical stability.
- No scikit-learn in this module.

Tests: gradient check against finite differences (relative error < 1e-5) on random
data; on a linearly separable toy set accuracy is 1.0; probabilities sum to 1;
**agreement with scikit-learn**: on a random 300 × 20 three-class problem,
`LogisticRegression(C=1/l2·…)` configured for the same objective gives probabilities
within 1e-3 (work out the exact `C` correspondence for the loss above and state it in
the test); save/load round trip; a class absent from `y` is simply not in `classes`.

## `embed.py`

```python
class Embedder(Protocol):
    dim: int
    def embed(self, texts: Sequence[str]) -> np.ndarray      # (n, dim) float32, L2-normalised

class FastEmbedEmbedder:      # BAAI/bge-small-en-v1.5 via fastembed (ONNX, CPU), dim 384
class HashEmbedder:           # deterministic test double: token hashes into `dim` buckets
def cached_embed(embedder, texts, cache_dir: Path) -> np.ndarray   # .npy per sha1(model + text) under data/cache/embed/
```

`fastembed` is imported lazily inside `FastEmbedEmbedder.__init__` (it is in the
optional `ml` group; tests and CI use `HashEmbedder` and must not download a model).
Texts are truncated to the first 2,000 characters before embedding.

## `features.py` (SPEC §7.3)

```python
FEATURE_NAMES: tuple[str, ...]
def edge_features(edge_view: EdgeView, embedder, boilerplate: BoilerplateScorer | None, cfg) -> np.ndarray
```

`EdgeView` = label, old text (joined with a space for two paragraphs; empty for
`added`), new text, `sim`, `changed_ratio`, Item, `is_table` (any side), cik, fiscal
year of the new filing. Features, in this order:

1. embedding of the old text (384; zeros when missing);
2. embedding of the new text (384; zeros when missing);
3. their difference (384);
4. `sim` (0.0 when NULL), `changed_ratio`, length ratio
   `min(n_old, n_new) / max(n_old, n_new)` (0 when a side is missing),
   `log1p(n_tokens_new)`, `log1p(n_tokens_old)`;
5. edge label one-hot over `modified, moved, split, merged, added, deleted`;
6. `boilerplate` of the new side (old side for `deleted`; 0.0 when no scorer);
7. Item one-hot `1A`, `7`, other; `is_table`;
8. numeric features from task 1.12: number of paired numbers, number of numeric alerts,
   largest `abs(rel_change)` capped at 5, largest percentage-point move capped at 100.

## Sampling and active learning (`cli.py`)

```
fl changes sample --n 100 --seed 20261115       seed batch -> eval/changes/queue.jsonl
fl changes next-batch --n 25                    highest predictive entropy among unlabelled
fl changes train [--write]
fl changes predict --universe NAME              fills change_pred
```

- Seed: from eligible pairs of `t1_rag`, edges labelled `modified`, `moved`, `split`,
  `merged`, `added`, `deleted` in Items 1A, 7 and others; stratified so that each edge
  label and each of {1A, 7, other} is represented, at most 5 edges per company.
  **Exclude every pair that is in `eval/alignment/sample.toml`** (keeps the alignment
  test pairs untouched by another labelling task).
- `next-batch`: train on all current labels; score a random pool of 5,000 unlabelled
  edges; take the 25 with the highest entropy, at most 3 per company; append to the
  queue. Stop suggesting at about 300 labels in total.
- Protocol for the author: seed 100, then batches of 25 until about 300.

## Training and evaluation (`train.py`)

- **Hold out by company:** `sklearn.model_selection.GroupKFold(n_splits=5)` with
  `groups = cik` (fewer splits if fewer than 5 companies have labels; fail below 3).
  Never split by paragraph. scikit-learn is used for the splitter and metric helpers
  only.
- `l2` chosen from `{0.1, 1, 10, 100}` by inner grouped cross-validation on the
  training folds (nested), not on the reported folds.
- Report: macro-F1 (mean and standard deviation over folds), per-class precision and
  recall, confusion matrix, label counts per class and per company, and the same
  metrics for two baselines on the same folds: majority class, and a one-feature rule
  `substantive if sim < 0.6 or label in (added, deleted)`.
- `--write`: fit on all labels, save `data/models/classifier_v{CLASSIFIER_VERSION}.npz`,
  write `eval/changes/results/{run_id}.json` (git commit, versions, number of labels,
  metrics) and the `classifier` section of `docs/RESULTS.md`. State in the section that
  labels come from a single annotator and how many there are.

## Labelling page

`fl label changes` → same local server, page `changes.html`: one edge at a time from the
queue; shows Item, heading path, company and fiscal years, old and new text side by side
with word-level difference highlighting, the aligner's label; six buttons (keys 1–6)
for the annotation labels plus "skip"; a link to open `eval/changes/GUIDE.md`. It shows
**no model prediction, score or boilerplate value** (that would bias the label). Each
answer is appended to `labels.jsonl` through the API. Progress counter.

`eval/changes/GUIDE.md`: the six definitions from SPEC §7.1, the definition of
*substantive* ("alters the information a reader has about the company"), and for each
label an empty "Examples" list that the **author** fills with 2–3 examples before
labelling. Definitions must not change mid-way without relabelling.

## Tests

Softmax tests above; features: shapes, zeros for missing sides, one-hots, names match
length; labels: append, duplicate refusal, resolve after edge ids change, unresolved
reported; train: on synthetic labels generated from a known linear rule over
`HashEmbedder` features, grouped CV runs and beats the majority baseline, and **no
company appears in both train and test of any fold** (assert on the fold indices);
`next-batch` returns the highest-entropy items of a hand-made pool; labeler API: next,
submit, resume; the page payload contains no prediction fields.

## Hand-over to the author

1. Fill the examples in `eval/changes/GUIDE.md` (2–3 per label).
2. `uv run fl changes sample --n 100 --seed 20261115`, then `uv run fl label changes`
   and label the 100.
3. Repeat: `uv run fl changes next-batch --n 25`, label them, until about 300.
4. Note the date the last label was made: the blind relabel pass (task 1.15) starts at
   least 7 days later.
5. Tell the lead; the lead runs `uv run fl changes train --write`.
