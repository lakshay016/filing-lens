# 1.11 — Author hand-aligns 20 test pairs; the single test run

Read `docs/briefs/README.md` Part A first. Then SPEC §6.5 ("The test pairs are scored
once, at the end") and brief `1.10-alignment-eval-dev.md`.

- **Branch:** `slice1/1.11-alignment-test`
- **Model:** Opus for the small code change; the lead runs the command personally.
- **Depends on:** 1.10 merged and its thresholds final; the aligner frozen
  (`ALIGNER_VERSION` will not change again before the run); the author's 20 test gold
  pairs committed.
- **Done when:** one result file `eval/alignment/results/*_test_*.json` exists with
  headline precision, recall and F1 on non-identical edges with 95% confidence
  intervals and the commit hash, and the `alignment-test` section of `docs/RESULTS.md`
  is generated from it.

## Order of events (the lead enforces this)

1. **Freeze.** Before the author labels the test pairs, everything that could be tuned
   is final: parser version, IDF file, `config/align.toml`, aligner code. Tag the commit
   `align-freeze-v1` (`git tag align-freeze-v1 && git push origin align-freeze-v1`).
   If the parser changes after labelling starts, gold hashes stop matching and the
   labels are lost; do not change the parser.
2. **Author labels** the 20 test pairs with `fl label align` (same rules as dev,
   `eval/alignment/README.md`), then commits `eval/alignment/gold/`. The author must not
   look at aligner output for these pairs before or during labelling.
3. **Agent** adds the single-run command below (this branch), with tests. The agent does
   not run it on real data.
4. **Lead** checks out the merged commit with a clean tree, runs
   `uv run fl eval alignment status` (all 20 complete and valid), then runs the test
   command once.
5. The numbers are what they are. No threshold, parser or aligner change is evaluated
   on the test pairs afterwards. Later improvements are reported against dev only, and
   the README says so.

## The command

```
fl eval alignment test-run --confirm "score the test set once"
```

- Refuses unless the `--confirm` text matches exactly.
- Refuses if any file matching `eval/alignment/results/*_test_*.json` already exists
  (message: the test set was already scored on <date> at <commit>).
- Refuses on a dirty git tree (anywhere, not just `src/`), and if `HEAD` is not at or
  after the tag `align-freeze-v1` with unchanged `src/filinglens/align/`,
  `src/filinglens/parse/` and `config/align.toml` since the tag
  (`git diff --quiet align-freeze-v1 HEAD -- <those paths>`).
- Refuses if any test gold file is missing, incomplete or invalid.
- Runs all methods (`full`, `difflib`, `greedy`, `no_moves`, `no_splitmerge`,
  `stages12`) on the 20 test pairs, Items 1A and 7, with the same metric code as dev.
- Writes the result file (same schema as dev, plus `"single_run": true` and the tag's
  commit) and regenerates the `alignment-test` section of `docs/RESULTS.md`: the
  headline row (full algorithm, non-identical P/R/F1 with CIs, N pairs, N edges, commit
  hash), the baseline rows, and the sentence "Test pairs were scored once, at commit
  <hash>".
- Prints the headline.

There is no `--force`. If the run crashes before writing the result file, fixing the
crash and running again is allowed (nothing was seen); say so in the report.

## Tests (synthetic gold in `tmp_path`, no real gold)

- Wrong or missing confirm text → refused.
- Existing test result file → refused.
- Dirty tree → refused (mock git).
- Changed aligner path since the tag → refused (mock git).
- Happy path on two synthetic pairs writes one file with `single_run: true`.
