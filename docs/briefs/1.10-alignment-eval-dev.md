## Metrics (`metrics.py`)

An edge is identified by its two sides as sets of paragraph positions:
`EdgeKey = (frozenset[int] old seqs, frozenset[int] new seqs)`. Predicted edges are
converted from paragraph ids to `seq`. Cross-Item `moved` edges are converted into, for
each Item under evaluation, the half that lies in that Item: a predicted cross-Item move
from Item 7 to Item 1A counts in Item 7 as `({old}, {})` and in Item 1A as `({}, {new})`
with label `moved` (gold was made per Item, so the author saw a deletion and an
addition there).

```python
@dataclass(frozen=True, slots=True)
class Counts:
    tp: int; n_pred: int; n_gold: int           # all edges
    tp_ni: int; n_pred_ni: int; n_gold_ni: int  # non-identical edges
    label_correct: int; label_total: int        # on matched edges

def count_item(pred: Sequence[PredEdge], gold: Sequence[GoldEdge]) -> Counts
def prf(tp: int, n_pred: int, n_gold: int) -> tuple[float, float, float]
def bootstrap_ci(per_pair: Sequence[Counts], *, n_resamples: int = 10_000,
                 seed: int = 20261115, alpha: float = 0.05) -> dict[str, tuple[float, float]]
```

Definitions:

- A predicted edge is **correct** when its `EdgeKey` equals the key of a gold edge.
- **All edges:** `tp` = correct predicted edges; precision = `tp / n_pred`; recall =
  `tp / n_gold`.
- **Non-identical edges (the headline):** an edge is *identical* when its label is
  `unchanged`. `n_pred_ni` = predicted edges not labelled `unchanged`; `n_gold_ni` =
  gold edges not labelled `unchanged`; `tp_ni` = predicted non-identical edges whose key
  equals a gold **non-identical** edge's key. (A predicted `modified` edge whose key
  matches a gold `unchanged` edge cannot occur: `unchanged` is decided by hash on both
  sides.)
- **Label accuracy:** over predicted edges that are correct, the share whose label
  equals the gold label. Report also a confusion table of labels.
- Micro-averaging: sum `Counts` over Items and pairs, then compute P/R/F1.
  `prf` returns `0.0` for a zero denominator.
- **Bootstrap over pairs** (pairs are the independent units; an Item is not): the unit
  is a filing pair, whose `Counts` is the sum over its two Items. Resample pairs with
  replacement `n_resamples` times with `numpy.random.default_rng(seed)`, recompute
  micro P/R/F1 from the summed counts, report the 2.5th and 97.5th percentiles for each
  of the six numbers.

## Baselines (`baselines.py`), same input and output types as the aligner

1. **`difflib`**: `difflib.SequenceMatcher(None, old_masked_hashes, new_masked_hashes,
   autojunk=False)`; `equal` blocks → 1-to-1 edges labelled by hash (`unchanged` or
   `rollforward`); within a `replace` block pair positionally up to the shorter length
   and label `modified`, the rest `added`/`deleted`; `insert`/`delete` blocks →
   `added`/`deleted`.
2. **Greedy best-match**: all pairs with `sim ≥ τ`, sorted by `(-sim, i, j)`, taken
   one-to-one with no ordering constraint (reuse `moves.greedy_pairs`); labels by hash,
   else `modified`; rest `added`/`deleted`. No `moved` label.
3. **Ablations of the full algorithm**: `enable_moves=False`; `enable_splitmerge=False`;
   both off. These use `align_filing` with the flags.

All run per pair through one function
`predict(method: str, old_by_item, new_by_item, aligned_items, sim_fn, cfg) -> dict[item, list[PredEdge]]`.

## Run (`run.py`, `fl eval alignment run`)

```
fl eval alignment run --split dev [--method full|difflib|greedy|no_moves|no_splitmerge|stages12|all] [--write]
fl eval alignment tune [--write]
```

- Loads `eval/alignment/sample.toml`, takes the pairs of the split, loads paragraphs
  from the database and gold files; runs `validate_gold` first and **fails** if any gold
  file is invalid or incomplete (a hash mismatch means the parser changed after
  labelling: stop and report; do not re-map silently).
- Evaluates Items 1A and 7 only.
- Uses the IDF model at `data/models/idf_v1.npz` and `config/align.toml`.
- Result file `eval/alignment/results/{run_id}.json`, `run_id` =
  `{UTC yyyymmddThhmmss}_{split}_{git short hash}`: split, methods, config, versions
  (`PARSER_VERSION`, `ALIGNER_VERSION`, IDF version), git commit (refuse `--write` on a
  dirty `src/` tree), per-method summed counts, P/R/F1 for all and non-identical edges
  with confidence intervals, label accuracy and confusion table, per-pair counts.
- `--write` also regenerates the `alignment-dev` section of `docs/RESULTS.md`: one row
  per method with non-identical P/R/F1 (CI), all-edge F1, label accuracy.

`tune` (dev only): grid `τ ∈ {0.30, 0.35, …, 0.70}` ×
`move_threshold ∈ {0.70, 0.80, 0.90}` × `split_gain ∈ {0.05, 0.10, 0.15}`
(`split_containment` fixed at 0.80). Objective: non-identical F1 on dev. Ties → the
values closest to the spec defaults (0.50, 0.80, 0.10). Prints the grid as a table,
writes it into the result file, and with `--write` stores the chosen values in
`config/align.toml` with a comment naming the run id. Ten pairs is a small sample: if
the best cell beats the defaults by less than the half-width of the default's
confidence interval, **keep the defaults** and say so in the output.

If thresholds change, bump `ALIGNER_VERSION` and re-run `fl align run --force` for the
universe before any later task uses stored edges.

## Tests

`test_metrics.py`, hand-built cases with exact expected numbers:

- Perfect prediction → 1.0 everywhere.
- Gold: 3 unchanged, 1 modified, 1 added, 1 deleted. Prediction gets the unchanged
  right, pairs the modified wrongly as added + deleted → compute by hand: all-edge
  `tp = 5` (3 unchanged + the true added + the true deleted), `n_pred = 7`,
  `n_gold = 6`; non-identical `tp_ni = 2`, `n_pred_ni = 4`, `n_gold_ni = 3`. Assert
  these exact counts.
- A `split` predicted as `modified` + `added` → neither key matches.
- Label accuracy: key matches, gold `moved`, predicted `modified` → counted in
  `label_total`, not in `label_correct`.
- Cross-Item move halves.
- Zero denominators.
- `bootstrap_ci`: identical per-pair counts → zero-width interval; deterministic for a
  seed; interval contains the point estimate on a varied example; resampling unit is
  the pair (a test with two pairs of very different sizes whose CI would be wrong if
  Items were resampled).

`test_baselines.py`: each baseline on E-style toy inputs from brief 1.7; the difflib
baseline on a swap yields no `moved`; partition property holds for every baseline.

`test_run.py`: the loader raises on `split="test"` without the explicit unlock
argument; result file schema; refuses a dirty tree with `--write` (mock the git call).

## Report to the lead

The dev table; the tuning grid; whether defaults were kept; per-pair non-identical F1
(to spot one pair dragging the result); the ten worst disagreements between the full
algorithm and gold, as `(pair, item, gold edge, predicted edge, first 150 characters of
each side)`. Disagreements are the most useful output of this task: say which look like
aligner errors, which like parser errors, and which like debatable gold.
