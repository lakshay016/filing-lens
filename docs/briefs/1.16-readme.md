## Rules

- **No number is typed by hand.** `scripts/readme_numbers.py` reads the recorded result
  files (`eval/alignment/results/*_test_*.json`, the latest dev result,
  `eval/changes/results/*.json`, `eval/runs/coverage_t1_rag.json`) and prints the values
  the README uses, each with its source file and JSON path. The README's results tables
  are written between `<!-- BEGIN numbers -->` / `<!-- END numbers -->` markers by
  `scripts/readme_numbers.py --write`. The test re-runs the script and fails if the
  README section differs from what the files say.
- If a result file is missing, the corresponding line reads "not yet measured"; never a
  guess and never a dev number in place of a test number.
- Do not describe anything that is not built. Slices 2 and 3 appear only under
  "Planned", in one short list.
- No return or backtest numbers of any kind (SPEC §11.4).
- Plain, factual wording. No superlatives, no "state of the art".
- No AI attribution anywhere.

## Structure

1. **What it is** — two or three sentences: tells you what changed in a company's 10-K
   since last year, by aligning the two filings paragraph by paragraph.
2. **Example** — a short real excerpt of a digest from `fl backfill` on a public
   filing (a numeric change and one top text change with old/new text). Public SEC text
   only.
3. **Results** (generated section):
   - Alignment: precision, recall, F1 on non-identical edges with 95% confidence
     intervals on the 20 hand-aligned test pairs; the `difflib` and greedy baselines and
     the two ablations in the same table; the sentence that test pairs were scored once
     and the commit hash.
   - Change classifier: company-grouped cross-validated macro-F1 with its spread, the
     number of labels, the two baselines.
   - Alerts: precision of shown alerts and precision@5 with interval, against the
     `1 − sim` baseline; Cohen's κ of the relabel pass.
   - Coverage: filings ingested, share parsed `ok`.
4. **How it works** — the pipeline in five short steps (fetch, parse into Items and
   paragraphs, align: anchors → dynamic programming → moves → split/merge, classify,
   rank), each with one sentence on why it is done that way, and a pointer to SPEC
   sections for detail. Include the DP recurrence in a code block.
5. **How the numbers were produced** — gold data made by hand with a tool that only
   pre-fills exact matches; dev/test split; bootstrap over filing pairs; classifier
   evaluated grouped by company; alerts judged blind on held-out companies; link to
   `eval/README.md`.
6. **Limitations** — from PRODUCT §7, honest and specific: 10-K only; US filers; gold
   covers Items 1A and 7 only; single annotator and a few hundred labels; boilerplate
   pool limited to the `t1_rag` companies; filings that fail to parse are excluded and
   counted; free-tier models for summaries; whatever the evaluation showed did not help
   (ablation rows that did not earn their place are named).
7. **Run it** — prerequisites (uv, Docker), `cp .env.example .env` and which three
   values to fill, `docker compose up -d`, `uv run fl db upgrade`,
   `uv run fl ingest --universe sample --limit 4`, `uv run fl parse --universe sample`,
   `uv run fl align fit-idf …`, `uv run fl backfill --ticker AAPL --years 2`. Every
   command must have been run by the agent exactly as written; paste nothing that was
   not executed.
8. **Data and licence notes** — SEC EDGAR fair-access (User-Agent, 8 requests/second);
   FinanceBench is CC BY-NC 4.0 and not redistributed; no licensed data in the
   repository; not investment advice.
9. **Planned** — slice 2 (versioned index and cited question answering), slice 3
   (research track; return effect not tested without survivorship-bias-free data).
