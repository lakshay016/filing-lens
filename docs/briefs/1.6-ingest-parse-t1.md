## Steps

1. `uv run fl universe check t1_rag` — every ticker resolves.
2. `uv run fl ingest --universe t1_rag`. This is about 500 documents at no more than
   8 requests/second; let it finish; run it a second time and confirm `fetched 0`.
   Failures are reported, not retried in a loop.
3. `uv run fl parse --universe t1_rag`.
4. `uv run fl report coverage --universe t1_rag --write`.
5. Commit `docs/RESULTS.md`, `eval/runs/coverage_t1_rag.json`, `eval/README.md`. Raw
   data stays under `data/` (ignored).

Run long commands in the background and poll; do not sit in a foreground call for
more than a couple of minutes.

## `report.py`

`docs/RESULTS.md` is a generated file made of named sections, so later tasks can add
theirs without overwriting others:

```markdown
# Results

Every number here is written by a command from a recorded run. Do not edit by hand.

<!-- BEGIN coverage -->
...generated...
<!-- END coverage -->
```

```python
def update_section(path: Path, name: str, body: str) -> None
    # replaces the text between the BEGIN/END markers of that name, or appends the
    # section if absent; creates the file with the header if missing; keeps other
    # sections byte-for-byte

@dataclass(frozen=True, slots=True)
class CoverageRow:
    fiscal_year: int; filings: int; fetched: int; ok: int; partial: int; failed: int

def coverage(session, ciks: Sequence[int], forms: Sequence[str]) -> list[CoverageRow]
def render_coverage(rows, reasons: Mapping[str, int], meta: RunMeta) -> str
def write_run_record(path: Path, payload: Mapping[str, Any]) -> None     # sorted keys, indent 2
```

`RunMeta`: universe name, number of companies, date (UTC), git commit hash
(`git rev-parse HEAD`; append `-dirty` if the tree has changes), `PARSER_VERSION`.

Rendered section: a line with the run metadata; a Markdown table
`Fiscal year | Filings | Fetched | ok | partial | failed | % ok` with a total row and a
separate "fiscal 2010 and later" row; then "Why filings are not `ok`" with reason counts;
then one sentence stating how many filings were excluded and that excluded filings are
counted, never guessed at. Percentages to one decimal.

`fl report coverage --universe NAME [--write]`: prints the section; with `--write`
updates `docs/RESULTS.md` and writes `eval/runs/coverage_{universe}.json` (rows,
reasons, meta). `--write` refuses to run when the git tree is dirty in `src/`, unless
`--allow-dirty` (the recorded commit must reproduce the number).

`eval/README.md`: a short table "number → command that produces it → file it is written
to", with the coverage row filled in and placeholder rows for alignment (1.10, 1.11),
classifier (1.13) and alert evaluation (1.15).

## Tests

- `update_section`: creates file; replaces only its own section; appends a new one;
  idempotent.
- `render_coverage`: fixed rows → exact expected Markdown (golden string in the test).
- `coverage` (`@pytest.mark.db`): a few synthetic filing rows across years and statuses
  → expected counts; amendments (`skipped`) are not counted as filings.
