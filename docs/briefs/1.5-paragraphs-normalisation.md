## `normalize.py`

```python
def norm_exact(text: str) -> str
def norm_masked(text: str) -> str
def sha1_hex(s: str) -> str                 # hashlib.sha1(s.encode("utf-8")).hexdigest()
def count_tokens(text: str) -> int          # len(norm_exact(text).split())
def exact_hash(text: str) -> str            # sha1_hex(norm_exact(text))
def masked_hash(text: str) -> str           # sha1_hex(norm_masked(text))

DATE_RE: re.Pattern[str]
YEAR_RE: re.Pattern[str]
NUMBER_RE: re.Pattern[str]                  # exported; task 1.12 reuses it
```

These are used for hashing and similarity only, never for display.

**`norm_exact`**: `unicodedata.normalize("NFKC", text)`, `.lower()`, replace every
character that is not a letter or digit (`str.isalnum()` false) with a space, collapse
whitespace, strip. So `"U.S. revenue: $1.2 billion"` → `"u s revenue 1 2 billion"`.

**`norm_masked`**, in this order:

1. NFKC, lower-case. Replace `<` and `>` with spaces (so the placeholders below cannot
   be forged by the text).
2. **Dates → `<date>`** (`DATE_RE`). `MONTH` = full month names and the abbreviations
   `jan feb mar apr jun jul aug sep sept oct nov dec` with an optional trailing `.`
   (`may` only as the full word). Patterns, tried longest first:
   - `MONTH D{1,2}(st|nd|rd|th)?,? YYYY` — `december 31, 2023`, `dec. 31 2023`
   - `D{1,2}(st|nd|rd|th)? MONTH,? YYYY` — `31 december 2023`
   - `MONTH,? YYYY` — `december 2023`
   - `MONTH D{1,2}(st|nd|rd|th)?` not followed by a digit — `december 31`
   - `M{1,2}/D{1,2}/(YY|YYYY)` — `12/31/2023`, `12/31/23`
   - `YYYY-MM-DD`
   `YYYY` here is `(19|20)\d\d`. A month name followed by neither a day nor a year is
   left alone (`may` the verb, `march` the verb).
3. **Years → `<year>`** (`YEAR_RE`): `(19|20)\d\d` standing alone: not preceded by a
   letter, digit, `.`, `,`, `$` or `-`, and not followed by a letter, digit, `%`, or by
   `,` or `.` plus a digit. So `fiscal 2023` → `fiscal <year>`, but `2,023`, `$2023`,
   `2023%`, `2023.5` are numbers (next step).
4. **Numbers → `<num>`** (`NUMBER_RE`). One match covers, in order: an optional opening
   bracket `(`; an optional sign `-`, `–` or `—`; an optional currency sign
   `$ € £ ¥` with optional space; the digits `\d[\d,]*(\.\d+)?` or `\.\d+`; an optional
   `%` (optional space before it) or the words `percent`, `per cent`, `basis points`,
   `bps`; an optional scale word `thousand|million|billion|trillion` (also `mm`, `bn`
   directly after the digits); an optional closing bracket `)` only if one was opened.
   **Guards:** the digits must not be glued to a letter on either side and not be part
   of a hyphenated code: not preceded by a letter, digit or by a letter plus `-`; not
   followed by a letter or by `-` plus a letter. So `10-k`, `10-q`, `8-k`, `1a`, `7a`,
   `covid-19`, `rule 10b5-1`, `g20`, `form s-3` keep their digits, while `note 12`,
   `401(k)` (→ `<num>(k)`), `3.5x` (kept: glued to `x`), `$1.2 billion`, `12%`,
   `(3,400)`, `1,234.5`, `25 basis points`, `-5%` become `<num>`.
5. Replace every character that is not a letter, digit, `<` or `>` with a space;
   collapse whitespace; strip. Result example:
   `"Revenue was $1.2 billion in fiscal 2023, up 12% from December 31, 2022."` →
   `"revenue was <num> in fiscal <year> up <num> from <date>"`.

Properties that must hold and are tested:

- Two texts that differ only in numbers, years or dates have equal `norm_masked`.
- `norm_masked` is idempotent on its own output except for the placeholders (do not
  test idempotence; test the examples).
- Texts that differ in a word have different `norm_masked`.
- Never raises on any `str` (hypothesis test with arbitrary text).

## `paragraphs.py`

```python
@dataclass(frozen=True, slots=True)
class ParagraphRecord:
    item: str
    seq: int                       # 0-based, global within the filing, document order
    heading_path: tuple[str, ...]
    text: str
    is_table: bool
    n_tokens: int
    exact_hash: str
    masked_hash: str

def build_paragraphs(blocks: Sequence[Block], segmentation: Segmentation) -> list[ParagraphRecord]
```

Rules, applied per section (`front` first, then each Item section in document order):

1. **Headings are not paragraphs.** They maintain `heading_path`, a stack: on a heading
   of level `L`, pop every entry whose level is ≥ `L`, then push it. The stack is empty
   at the start of each section. The Item's own heading (the section's
   `heading_index` block) is not in the path. `heading_path` of a paragraph is the stack
   texts at that point, outermost first, each truncated to 200 characters.
2. **Text blocks** become paragraphs, with the merge rule: a `text` block that is
   shorter than 40 characters and is not a list item is held as a pending prefix.
   Several consecutive short blocks accumulate, joined by a space. When the next block
   is a `text` block (list item or not), its paragraph text is
   `pending + " " + block.text` and the pending prefix is cleared. When the next block
   is a heading, a table, or the section ends, the pending prefix is emitted as its own
   paragraph (text is never dropped).
3. **List items** are always their own paragraph (a pending prefix may be glued in
   front of the first one as in rule 2; a list item is never itself held as a prefix).
4. **Table blocks** become one paragraph with `is_table = True` and
   `text = caption + "\n" + block.text` when the block has a caption, else `block.text`.
5. Drop a paragraph whose `norm_exact` is empty.
6. `seq` counts emitted paragraphs from 0 across the whole filing.
7. `n_tokens`, `exact_hash`, `masked_hash` from `normalize`.

## Pipeline change (`parse/pipeline.py`)

Inside `parse_filing`, in the same transaction as the status update:

1. Delete `alignment_pair` rows where `old_filing_id` or `new_filing_id` is this filing
   (their edges cascade). Paragraph ids are about to change, so stored alignments of
   this filing are stale.
2. Delete the filing's `paragraph` rows.
3. If the status is `ok` or `partial`, bulk-insert the new paragraphs. A `failed`
   filing stores none.

Add to the parse report (task 1.4's `fl parse --report`) one more line per run:
total paragraphs stored and the median paragraphs per filing.
