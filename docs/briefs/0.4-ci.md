Read `docs/briefs/README.md` Part A first. Then SPEC §13.

- **Branch:** `slice0/0.4-ci`
- **Model:** Sonnet
- **Depends on:** 0.1, 0.2, 0.3 merged
- **Done when:** the workflow run on this task's own pull request is green

## Files

Create: `.github/workflows/ci.yml`. Nothing else changes, unless a check fails on CI for
a reason that is a real bug in earlier work; then stop and report instead of patching
around it.

## Workflow

- Name `CI`. Triggers: `pull_request` (all branches) and `push` to `main`.
- `permissions: contents: read`. `concurrency`: group `ci-${{ github.ref }}`,
  `cancel-in-progress: true`.
- One job `checks`, `runs-on: ubuntu-latest`, `timeout-minutes: 15`.
- Service container `postgres`: image `pgvector/pgvector:pg16`; env
  `POSTGRES_USER=filinglens`, `POSTGRES_PASSWORD=filinglens`, `POSTGRES_DB=filinglens`;
  ports `5433:5432`; options
  `--health-cmd "pg_isready -U filinglens -d filinglens" --health-interval 2s --health-timeout 5s --health-retries 30`.
- Job env:
  ```yaml
  FL_DATABASE_URL: postgresql://filinglens:filinglens@localhost:5433/filinglens
  FL_REQUIRE_DB: "1"
  FL_LLM_MODE: replay
  ```
  No secrets. Never reference `DATABASE_URL`, API keys or `FL_SEC_USER_AGENT` in the
  workflow.
- Steps, in order:
  1. `actions/checkout@v4`
  2. `astral-sh/setup-uv@v5` with `enable-cache: true`
  3. `uv sync --locked --all-groups`
  4. `uv run python scripts/check_licensed_data.py`
  5. `uv run ruff check .`
  6. `uv run ruff format --check .`
  7. `uv run mypy`
  8. `uv run alembic upgrade head`
  9. `uv run pytest`
- Python comes from `.python-version` through uv; do not add `actions/setup-python`.

Check the current major versions of the two actions before pinning (`gh api
repos/astral-sh/setup-uv/releases/latest --jq .tag_name`); use the latest major tag.

## Notes

- Cost: GitHub-hosted runners are free for public repositories and have a free monthly
  allowance for private ones. The job should finish in about two minutes; if it takes
  more than five, say so in the report.
- Tests must not use the network. If a test fails on CI because it tried to reach the
  internet, that is a bug in the test; report it.

## Review checklist (lead)

- [ ] `gh pr checks` green; open the run log and confirm all nine steps ran and that
      pytest reports the `db` tests as passed, not skipped.
- [ ] The workflow contains no secret references.
- [ ] `gh run list --workflow CI --limit 1` duration is reasonable.
