```python
@dataclass(frozen=True, slots=True)
class Message: role: Literal["system", "user", "assistant"]; content: str

@dataclass(frozen=True, slots=True)
class LLMResult:
    text: str; json: Any | None; provider: str; model: str
    tokens_in: int | None; tokens_out: int | None; latency_ms: int; cached: bool

class LLMUnavailable(RuntimeError): ...      # no allowed provider could answer
class LLMCacheMiss(RuntimeError): ...        # replay mode and the request is not cached

class LLMClient:
    def __init__(self, config: ModelsConfig, settings: Settings, *, cache_dir: Path,
                 transport: httpx.AsyncBaseTransport | None = None) -> None
    async def complete(self, messages: list[Message], *, schema: dict | None = None,
                       privacy: Literal["public", "private"] = "public",
                       purpose: str) -> LLMResult
```

Behaviour:

- Provider order = `purposes[purpose][privacy]`. **A `private` request is sent only to
  providers with `private_ok = true`.** This is checked twice: when the config is
  loaded (a provider listed under `private` without `private_ok` is a config error) and
  again immediately before each request. A private request never falls through to a
  non-private provider; when its providers fail it raises `LLMUnavailable`.
- Request: `POST {base_url}/chat/completions` (OpenAI-compatible) with
  `Authorization: Bearer <key>`, `temperature: 0`, and, when `schema` is given,
  `response_format: {"type": "json_schema", "json_schema": {"name": "out", "schema": schema}}`;
  parse and validate the JSON reply against the schema's required keys.
- A provider whose key is not set is skipped. On 429, 5xx or timeout: move to the next
  allowed provider (no retry loop on the same one). Per-provider client-side spacing of
  `60 / requests_per_minute` seconds between requests.
- **Cache** (`cache.py`): key = sha256 of the canonical JSON of
  `{messages, schema, model, temperature}` (sorted keys). Stored as
  `{cache_dir}/{key[:2]}/{key}.json` with the result and the provider. Cache lookup is
  tried for each allowed provider's model in order before any network call.
- **Replay mode** (`settings.llm_mode == "replay"`): a cache miss raises `LLMCacheMiss`;
  no socket is opened. Tests and CI always run in replay mode.
- Keys never appear in logs, exceptions or the cache.

## Ranking (`changes/rank.py`, SPEC §7.5)

```python
def item_weight(item: str, weights: Mapping[str, float]) -> float      # "1A" 1.0, "7" 0.9, else "other" 0.6
def alert_score(p_substantive: float, boilerplate: float, item: str, weights) -> float
    # p_substantive * (1 - boilerplate) * item_weight
def rank_filing(session, new_filing_id: int, cfg) -> list[AlertRow]
```

For the pair whose new filing is given: text alerts = edges with a `change_pred` row
(classifier-decided labels), sorted by `(-alert_score, edge id)`, top
`cfg.top_text_alerts` (10), `kind = 'text'`, `rank` from 1. Numeric alerts = **all**
`numeric_alert` rows of the pair, `kind = 'numeric'`, ranked by the larger of
`abs(rel_change)` and `points / 100`. Replace the filing's existing `alert` rows.
`fl changes predict` (task 1.13) must have filled `change_pred`; `rank_filing` runs the
prediction for the pair if rows are missing.

`update_change_intensity`: now that edges are classified, fill
`alignment_pair.change_intensity` = `change_intensity_raw` computed without the edges
whose predicted class is `cosmetic` (argmax of the three probabilities).

## Summaries (`changes/summarize.py`)

For each shown **text** alert: one call, `purpose="summary"`. System message: "You
summarise one change between two versions of a paragraph from a company's annual
report. Say what changed in one or two plain sentences. Use only the text given. Do not
give advice or opinions." User message: Item, heading path, `OLD:` text, `NEW:` text
(each truncated to 4,000 characters; `(none)` for a missing side). The paragraph text is
**untrusted input**: it is passed as data inside the user message, the reply is used
only as display text, is stripped of markup, and truncated to 400 characters.

`privacy`: `"private"` when the run was started for holdings (`fl watch`, or
`fl backfill` for a ticker that is in the holdings file), otherwise `"public"`. The
company name and ticker are **not** included in the prompt in either case.

On `LLMUnavailable` or `LLMCacheMiss`: the alert keeps `summary = NULL`; nothing else
fails. Store `summary_model` as `provider/model`.

## Pipeline and watcher (`watch/`)

```python
def process_company(cik, *, years: int | None, holdings: bool, deps) -> list[FilingResult]
    # ingest (submissions + download) -> parse -> align new pairs -> numeric alerts
    # -> predict -> rank -> summarise. Each step reuses the existing functions; this
    # module only orchestrates. Idempotent: finished work is skipped.

def new_accessions(session, cik, filing_list) -> list[FilingMeta]        # poll.py
def render_digest(results: Sequence[FilingResult], today: date) -> str   # digest.py
```

- Holdings: `get_settings().holdings_file` (`holdings.local.toml`), format
  `tickers = ["AAPL", …]`, no quantities. If the file does not exist, `fl watch` exits
  with a message telling the author to copy `holdings.sample.toml`; it does not fall
  back silently.
- `fl watch`: for each holding, fetch the filing list, find 10-K accessions not in the
  manifest, run `process_company` for them with `holdings=True`. Writes
  `data/digests/{YYYY-MM-DD}.md` (appends a numbered suffix if the file exists) and the
  `alert` rows. Prints "no new filings" when there are none. Nothing that identifies the
  holdings is logged above DEBUG.
- `fl backfill --ticker X --years N`: same pipeline over the last `N` fiscal years of
  one company (needs `N + 1` filings to form `N` pairs), writing
  `data/digests/backfill-{ticker}-{date}.md`.
- Scheduling is a local job: document one `launchd`/`cron` line in the digest module's
  docstring; do not install anything.

Digest (Markdown): per filing a header (company, fiscal year, filing date, EDGAR link
`https://www.sec.gov/Archives/edgar/data/{cik}/{accession_nodash}/{primary_document}`),
coverage notes (Items not aligned and why; Items present only in the new filing, for
example a new Item 1C), then "Numeric changes" (old → new, context) and "Top changes"
(rank, Item and heading path, class and score, summary if any, old and new text with a
word-level diff rendered as `~~deleted~~` and `**inserted**`, each side truncated to
1,200 characters). A filing with no eligible prior year says so instead of showing
nothing. The footer states: "Research tool output. Not investment advice."

## Tests

- `test_client.py` (`respx`, `llm_mode="live"` only inside these tests with mocked
  transport): **a private request is never sent to Gemini** — even when Groq returns
  429, 500 or times out, and even when Gemini is the only provider with a key; it raises
