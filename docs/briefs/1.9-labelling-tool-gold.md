## The rule that must not be broken

The tool pre-fills **exact-hash matches only**: a link is suggested when a paragraph's
`exact_hash` occurs exactly once on each side. Nothing else may guide the author: no
TF-IDF similarity, no output of `filinglens.align`, no "most similar paragraph"
suggestions, no ordering by similarity. The tool must not import `filinglens.align` at
all (a test enforces this). Otherwise the gold data inherits the aligner's mistakes and
the headline number is worthless.

## Gold format (`evalalign/gold.py`)

One file per (pair, Item): `eval/alignment/gold/{old_accession}__{new_accession}__{item}.jsonl`.

Line 1 is a header, the rest are edges:

```json
{"type": "header", "old_accession": "...", "new_accession": "...", "item": "1A",
 "parser_version": "3", "n_old": 212, "n_new": 220, "complete": true,
 "labelled_at": "2026-11-20T15:04:05Z", "seconds_spent": 5400}
{"type": "edge", "label": "modified",
 "old": [{"seq": 41, "hash": "<exact_hash>"}],
 "new": [{"seq": 43, "hash": "<exact_hash>"}], "prefilled": false}
```

Paragraphs are identified by `seq` (position in the filing) plus `exact_hash`; never by
database id.

```python
@dataclass(frozen=True, slots=True)
class GoldRef: seq: int; hash: str
@dataclass(frozen=True, slots=True)
class GoldEdge: label: Label; old: tuple[GoldRef, ...]; new: tuple[GoldRef, ...]; prefilled: bool
@dataclass(frozen=True, slots=True)
class GoldFile: header: GoldHeader; edges: tuple[GoldEdge, ...]

def gold_path(root: Path, old_accession: str, new_accession: str, item: str) -> Path
def load_gold(path: Path) -> GoldFile
def save_gold(path: Path, gold: GoldFile) -> None            # atomic: temp file + os.replace
def validate_gold(gold: GoldFile, old: Sequence[ParaView], new: Sequence[ParaView]) -> list[str]
def derive_label(old: Sequence[ParaView], new: Sequence[ParaView], moved: bool) -> Label
def prefill(old: Sequence[ParaView], new: Sequence[ParaView]) -> list[GoldEdge]
```

`ParaView` = `(seq, text, heading_path, is_table, exact_hash, masked_hash)` read from
the `paragraph` table.

`validate_gold` returns problems (empty list = valid): a `seq`/`hash` that does not
match the current paragraphs (the parser changed since labelling); a paragraph in two
edges; when `complete`, a paragraph in no edge; an edge whose shape does not match its
label (SPEC §6.1 table).

`derive_label`: the author decides the links; the label follows from them. 1 old + 1
new: `moved` if the author ticked "moved", else `unchanged` if `exact_hash` equal, else
`rollforward` if `masked_hash` equal, else `modified`. 1 old + 2 new: `split` (the two
new must be adjacent in `seq` order within the Item list, otherwise reject). 2 old + 1
new: `merged` (same adjacency rule). 0 + 1: `added`. 1 + 0: `deleted`. Anything else is
rejected with a message.

`prefill`: unique-on-both-sides `exact_hash` matches → `unchanged` edges with
`prefilled = true`. Nothing else.

## Sampling (`evalalign/sample.py`, SPEC §6.5)

`fl eval alignment sample --universe t1_rag --seed 20261115 [--n 30] [--write]`

- Candidate pairs: consecutive original 10-Ks of one company (same planning rule as the
  aligner: one filing per fiscal year, period gap 270–460 days) where Items 1A and 7 are
  both `ok` on both sides. This is computed from `filing` rows; do not call the aligner.
- Strata: SIC division × era of the new filing (`2006–2012`, `2013–2019`, `2020–`) ×
  length tercile (terciles of the new filing's Item 1A + Item 7 character count over
  all candidates).
- Draw with `random.Random(seed)`: shuffle the strata's pairs, then round-robin over
  strata sorted by name, taking one pair per stratum per round, at most 2 pairs per
  company, until `n` pairs are chosen.
- Restructuring: SPEC requires at least 6 pairs with visible restructuring. The tool
  does not decide this. It prints, for every candidate pair, a *heading-change score*:
  `1 - difflib.SequenceMatcher(None, old_headings, new_headings).ratio()` over the lists
  of level-2 and level-3 heading texts of Items 1A and 7 (from `heading_path`; this uses
  no paragraph similarity). `--write` reserves 6 of the 30 slots: it lists the 15
  highest-scoring candidates not already drawn in a `[[restructuring_candidates]]`
  block, and the **author** picks 6 by moving them into `[[pairs]]`.
- Split: after the 30 are fixed, `fl eval alignment sample --assign-split` shuffles with
  the same seed and marks 10 `dev` and 20 `test`, keeping at least 2 restructured pairs
  in dev and 4 in test.

Output `eval/alignment/sample.toml`: `seed`, `universe`, `created`, `parser_version`,
then `[[pairs]]` entries with `cik`, `ticker`, `old_accession`, `new_accession`,
`fiscal_year`, `stratum`, `restructured` (bool), `split` (`dev`/`test`/empty).

`fl eval alignment status` prints, per pair and Item, whether a gold file exists,
whether it is complete and valid, counts by label, and time spent.

## The tool (`tools/labeler`)

Local only. `fl label align [--port 8765]` starts a FastAPI app with uvicorn bound to
`127.0.0.1` and prints the URL. No authentication, no external resources: the page
loads no CDN script, font or image (it must work offline).

API (JSON):

```
GET  /api/pairs                         pairs from sample.toml with per-Item status
GET  /api/pair/{old}/{new}/{item}       both paragraph lists + current edges (gold file if present, else prefill)
PUT  /api/pair/{old}/{new}/{item}       body: edges + complete flag + seconds_spent; validates, saves atomically
```

The server recomputes every label with `derive_label` and rejects invalid shapes; the
browser never sends a label it made up. `PUT` with `complete = true` fails with the list
of problems if any paragraph is unassigned.

Page (plain HTML + JavaScript, no build step, no framework):

- Left column old filing, right column new filing; each paragraph is a card with its
  `seq`, heading path (small, grey), text, and a table marker. Two independent scroll
  panes, plus a "sync scroll" toggle that scrolls both proportionally.
- Linked paragraphs share a colour band and an edge number. Pre-filled exact matches
  are shown collapsed to one line (they are most of the document) with a toggle
  "show unchanged".
- Linking: click an old card, then a new card → 1-to-1 edge. Shift-click to add a
  second card on one side (for split/merged). A checkbox "moved" on a 1-to-1 edge.
  Click an edge number and press Delete (or the × on the card) to unlink.
- "Mark rest as added/deleted": assigns every still-unlinked paragraph in the current
  view to `added`/`deleted`. It asks for confirmation and shows the count first; the
  author must have looked at them.
- Text search box per column (plain substring, case-insensitive) that highlights and
  jumps. Search is by text only; there is no similarity search.
- Word-level highlighting of differences inside an already linked 1-to-1 pair (a
  display aid computed in the browser from the two texts; it never suggests links).
- Autosave every change (debounced `PUT` with `complete = false`); a "Finish Item"
  button sends `complete = true`. A timer counts active seconds (stops after 60 s
  without input). Keyboard: `j`/`k` next/previous unlinked paragraph in the focused
  column, `u` toggle unchanged, `m` toggle moved on the selected edge.
- Header shows progress: unlinked old, unlinked new, edges by label.

`tools/labeler/README.md` and `eval/alignment/README.md`: how to start it, the labelling
rules below, and the file format.

## Labelling rules for the author (put these in `eval/alignment/README.md`)

1. Link two paragraphs when they are the *same paragraph*: the same point in the same
   place in the argument, even if reworded. If the topic is the same but the text was
   rewritten from scratch, it is still the same paragraph when a reader would say "this
   replaced that".
2. If nothing in the other filing plays that role, leave it `added` / `deleted`.
3. Tick "moved" when the paragraph sits in a different position relative to its
   linked neighbours (it jumped over at least one other linked paragraph).
4. Use two-on-one-side only when one paragraph was cut in two adjacent ones, or two
   adjacent ones were joined.
5. Tables are paragraphs too. A table whose numbers changed but whose rows are the
   same is linked (the tool will call it `rollforward`).
6. When unsure, write the case in `eval/alignment/NOTES.md` and decide the same way
   every time. Do not look at aligner output while labelling.
